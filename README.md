# AutoCommit

开发者：Jason Jia

AutoCommit 根据所选变更和项目规范生成可审核的提交说明。Visual Studio 2019（16.x，x86）与 Visual Studio 2022 17.14（x64）使用共享 C# 代码，支持 Git 和 TFVC。VS Code 桌面扩展支持 Git，并共用项目中的 `.auto` 模型配置与提交规范。

下载见 [GitHub Release v1.0.3](https://github.com/Haiezan/AutoCommit/releases/tag/v1.0.3) 和[本地安装包及校验值](releases/LATEST.md)。各平台使用各自的 VSIX。阅读[运行逻辑与流程图](docs/runtime.md)，或查看 [VS Code 使用说明](src/AutoCommit.Vscode/README.md)。

## v1.0.0 正式版本

AutoCommit 将 Git 或 TFVC 变更、项目自己的提交规范和 OpenAI 兼容模型连接起来，生成供开发者审核的提交说明。Visual Studio 集成 Git 与 TFVC 工作流；VS Code 扩展读取 Git 暂存区，并把结果填入原生提交框。

| 编辑器 | 仓库类型 | 审核后的操作 |
| --- | --- | --- |
| Visual Studio 2019、Visual Studio 2022 17.14 | Git、TFVC | 确认后在插件内执行本地 Git 提交或 TFVC 签入 |
| VS Code 桌面版 | Git | 将说明回填到原生 Git 提交框，由用户执行提交 |

主要功能：

- **按所选范围读取变更。** Git 以暂存区为准，支持部分暂存；Visual Studio 和 VS Code 均可在空暂存区时经用户确认暂存全部变更。Visual Studio 的 TFVC 读取所选映射目录与 Team Explorer「包含的更改」的交集。
- **按项目约定生成。** 使用 OpenAI 兼容的模型服务，可设置 Base URL、模型、请求超时、单次输入预算及可选思考参数。项目 `.auto/model.json` 和 `.auto/commit-rules.md` 优先于内置默认值；API Key 分别保存在 Windows DPAPI 或 VS Code SecretStorage 中。
- **处理大型差异和超时。** 超过预算时分批提取逐文件事实，保留文件来源编号，按最终请求容量压缩相邻摘要，再结合项目规范生成。请求超时可重试或缩小批次；失败时提供标明覆盖范围的部分摘要或本地摘要。
- **保护草稿与提交范围。** 生成前后校验变更快照，Visual Studio 提交或签入前再次核对；取消、快照变化或拒绝替换时保留原稿。Git hooks 与签名设置继续由 Git 处理。
- **查看运行过程。** 显示阶段、进度、耗时和模型返回的 Token 用量；提供运行日志和固定文本连接测试。示例生成命令使用固定示例差异，不发送仓库内容。
- **明确外发与写入行为。** 只有用户点击生成时才会发送所选变更及规范到配置的模型服务；HTTP 需显式允许。插件不会自动推送，也不会绕过 TFVC 团队策略。

Release 构建通过，33 项 .NET 测试与 19 项 VS Code 测试通过，三个安装包版本及 SHA-256 校验值已核对。自动化测试不代替 Visual Studio / VS Code 实机 GUI 验收；真实模型服务和 TFVC 服务器也未在此次发布中联调。VS Code 包含工具报告未提供 LICENSE 文件，但打包成功。

### 0.6.0 Release：TFVC 与独立连接状态

VS2019 新增 TFVC 工作区支持，使用 VS 安装的 Team Explorer 客户端组件及其认证环境。请先在 Team Explorer 连接 TFS / Azure DevOps Server 并映射工作区；不需要把 TFS 凭据填入模型 API Key。

- 优先识别 Git；非 Git 目录尝试当前用户的 TFVC 本地工作区映射。自动选择项目/解决方案目录，也可手工指定工作区内子目录。
- 读取指定目录递归范围内的挂起更改；新增、编辑、删除、重命名和目录操作均提供元信息。文本以工作区基线与本地内容两段供模型比较，不是统一 diff。
- 只读取已经挂起的修改。先在 VS 中检测并挂起新增、删除等更改；不自动添加文件，不代表 Team Explorer 的勾选列表。
- 非 UTF 编码、二进制和超过 1MB 文件仅提供元信息；使用内容哈希检测变化。输入过大时拒绝，建议缩小目录范围。
- TFVC “签入 TFS 服务器”是远程写入。确认框明确目录和范围，签入前重新检查快照，评估冲突、签入说明和团队策略。不覆盖策略、不绕过门控签入。需工单、必填注释或门控流程时请复制到 Team Explorer 完成签入。
- 模型状态、仓库状态在底部分开显示，仓库识别失败不会覆盖模型测试结果。无仓库时仍可测试模型。
- `.auto` 位于当前选定的 TFVC 目录（Git 则位于仓库根目录），不会自动挂起这些配置文件。

依赖：VS2019 Team Explorer 的 TFVC 客户端组件。若提示 Microsoft.TeamFoundation 程序集缺失，请通过 VS Installer 修复 Team Explorer/相关工作负载，再重启 VS。

验证：VS2019 Release 编译及 14 项自动化测试通过（包括 TFVC 文本编码、二进制元信息和内容哈希测试）。**当前没有 TFS 服务和 VS 实机，TFVC 认证、工作区读取、策略、签入及 GUI 加载尚未联调验证**。请先在测试项目验证新增/编辑/删除/重命名、范围外修改不签入、读取后修改被拒绝、签入返回 Changeset，以及拒绝策略时保留说明。

### 0.5.0 Release：项目配置

首次成功识别并读取 Git 仓库时，在仓库根目录初始化 `.auto`。每个仓库共享一份配置，不为每个 csproj 重复创建。

- `.auto/model.json`：BaseUrl、Model、AllowHttp、MaxInputCharacters，可纳入版本控制。对支持的模型可用 `EnableThinking` 显式开启或关闭思考。API Key 只在本机保存。
- `.auto/commit-rules.md`：项目提交规范，可编辑并共享。第一次创建时优先复制原 `.commit-rules.md`，否则使用完整内置规范；之后以 `.auto` 为准，不覆盖已有文件。
- `.auto/.gitignore`：排除常见本地凭据文件名，仅是辅助保护，不替代正确保管 Key。
- Key 在插件设置页填写并保存至 `%LOCALAPPDATA%/AutoCommit/credentials`，使用 DPAPI 加密，同一服务地址默认使用本机共享 Key，也可为项目保存专用 Key 或选择不发送 Key。VS2019 和 VS2022 共用此存储，VS Code 使用独立的 SecretStorage。
- 未识别仓库时保存的是全局默认设置，之后作为新仓库 model.json 的初始值。共享配置或规范修改后，点击“读取暂存变更”加载。
- 创建文件会在 Git 中显示为未跟踪文件，由用户决定是否暂存和共享；插件不会自动暂存。

**0.5.0 历史支持边界：TFS/Azure DevOps 托管的 Git 支持；TFVC 在 VS2019 0.6.0 新增。** `.auto` 配置可用于 Git 与 TFVC 范围。

0.5.0 的历史发布文件位于 `releases/0.5.0`，含 VS 2019、VS 2022 独立 VSIX 及 SHA-256 校验值。Release 指构建配置，不表示已通过 VS 实机验收。

### 0.4.0 交互更新

- 重新生成前明确确认覆盖，默认聚焦取消；包含手动修改时特别提示。
- 新响应成功且快照验证通过才替换原文；失败、超时、取消保留原文。

- 读取变更、切换仓库保留说明；过期状态禁用直接提交，仍可复制。重新显示工具窗口不会自动清空内容。
- 生成期间结果只读；提交后保留说明和结果，禁止重复提交。
- 模型设置保存后收起；差异和规范分别折叠；编辑器随窗口高度伸缩，操作区固定且可换行。
- 默认主题资源适配、可访问名称、取消默认焦点、标题长度建议及明确状态文字。
- 连接测试与生成用量独立；展示的生成用量对应原始响应，手动编辑不会改变其数值。失败请求不以零用量代替未知。
- 网络、HTTP、身份配置及签名错误提供处理建议；保留 Git 原始失败输出帮助排查 hooks。

草稿与撤销历史仅保存在当前工具窗口内存中，不承诺关闭 VS 或重新创建窗口后恢复。

## 已实现

- 工具菜单入口、分区 WPF 工具窗口：可折叠模型配置、差异/规范选项卡、可编辑结果、固定底部操作区。
- 独立测试连接（仅发送固定文本，可能产生少量调用费用）、保存配置、进度与取消、结果字数提示。
- 自动识别选中项目、解决方案或活动文件所在 Git 仓库，保留手工指定入口；显示分支及变更统计。
- 差异与 Markdown 规范默认收起，按需展开。无仓库规范文件时使用完整内置规范。
- 显示本次生成的请求次数、耗时和服务端返回的 Token 用量。分批生成时使用本次请求的合计，未返回的字段显示为未知。连接测试单独显示用量。
- 审核后确认提交到本地 Git，提交前检查分支及暂存快照；保留 Git hooks 和签名设置，不推送。
- 自定义 OpenAI 兼容 Base URL、模型、API Key；支持本机和局域网兼容服务。
- 读取 `.auto/commit-rules.md`，可临时编辑提示规范；持久修改请编辑该文件。
- 生成、取消、编辑和复制；生成前后及复制前验证暂存快照。
- API Key 通过 DPAPI 按 Windows 用户加密，凭据位于 `%LOCALAPPDATA%/AutoCommit/credentials`，项目配置位于 `.auto`。
- Git 和 TFVC 超出单次模型输入预算时自动分批汇总，再逐层合并。HTTP 需要用户明确启用，模型请求禁用重定向。

## 使用

从[下载页](releases/LATEST.md)选择匹配 Visual Studio 版本的安装包。安装后重启，在「工具 → AutoCommit 提交助手」打开窗口。以下路径用于自行构建 Debug VSIX。

| Visual Studio | 安装包 |
| --- | --- |
| 2019（16.x） | `src/AutoCommit.Vsix.VS2019/bin/Debug/net472/AutoCommit.Vsix.VS2019.vsix` |
| 2022（17.14） | `src/AutoCommit.Vsix/bin/Debug/net472/AutoCommit.Vsix.vsix` |

两个包均要求 .NET Framework 4.7.2 或更高版本。VS 2019 包使用 16.0 SDK 编译，安装清单限定 `[16.0,17.0)`；VS 2022 包使用 17.14 SDK。VSIX 构建工具统一使用 17.x，但不会作为扩展运行依赖打包。

1. 打开工具窗口，在「提交说明」页核对当前仓库和变更数。点击「刷新」重新读取；需要其他目录时展开「切换范围」。Git 可先暂存本次提交的文件，或在暂存区为空时点击「暂存全部并生成说明…」，确认暂存全部更改。TFVC 请先打开 Team Explorer 的「挂起的更改」，将准备签入的文件移入「包含的更改」。插件读取选定目录及其子目录内的包含项。读取不会自动创建项目配置文件。
2. 点击「配置模型」或打开「设置」页，填写 Base URL（例如 `http://localhost:11434/v1`）及实际已部署模型名。本机 HTTP 也需勾选允许 HTTP。无认证服务可以留空 Key。测试连接会发送固定文本并可能产生少量费用。
3. 在「更改认证方式」中选择共享、项目专用、恢复共享或不发送 Key，再执行对应操作。如需保存配置，点击“保存项目配置”或“保存本机默认配置”。Key 通过“保存本机共享 Key”或“保存项目专用 Key”单独保存。“恢复使用共享 Key”可解除当前项目的覆盖。首次保存项目配置时会提示将创建的 `.auto` 文件。无需保存也可以用当前设置生成。
4. 在「查看变更」页核对文件清单，可临时编辑提交规范。文件清单、差异预览和当前规范均可放大查看；选择「打开 Markdown 文件」可在 VS 编辑器中修改项目规范。回到「提交说明」页，核对目标服务后点击「生成提交说明」。AutoCommit 将所选变更和规范发送到配置的模型服务。`MaxInputCharacters` 默认每次请求 48,000 字符，超出后会分批处理，实际发送的差异可以多于本地预览。详细流程见[生成与合并流程图](docs/runtime.md#分批生成与合并)。
5. 审核说明和文件范围。可以复制到 IDE 的原生提交框，也可以在 Visual Studio 插件内确认后执行本地 Git 提交或 TFVC 签入。

运行日志位于 VS Code 的「输出 → AutoCommit」或 Visual Studio 的「运行详情 → 打开日志目录」。VS Code 还提供「AutoCommit: 用示例变更测试生成」，使用固定示例差异验证模型生成，不读取或发送仓库内容。已提取的事实附带文件来源，超出最终请求预算时才压缩摘要。

进度区会显示当前批次和合并阶段，用户可以取消。单次模型请求默认等待 240 秒，可在项目 .auto/model.json 中通过 `RequestTimeoutSeconds` 设置为 1 至 300 秒。小差异直接生成、摘要合并和最终生成超时时，插件会重试当前请求一次。较大的差异请求超时后，插件会缩小批次继续汇总，并保留已完成的摘要。超时提示包含阶段、输入大小和耗时。如果最终生成失败，插件用已提取事实生成「部分摘要」并列出覆盖尚未确认的文件。尚无提取结果时，插件按文件清单生成「本地摘要」。替换已有说明前会询问。用户取消或快照变化时保留原说明。

插件不会自动暂存或推送；仅在用户明确确认后提交。提交执行期间禁用取消，避免中断 Git 写入后无法判断结果；Git hooks 或签名工具可能需要在外部完成交互。请避免提交期间在其他窗口并发修改暂存区；提交前检查不是跨进程事务锁，hooks 也可修改内容。点击生成才会发送所选变更与规范；请确认服务地址适合接收该仓库代码。当前版本没有自动敏感信息检测。

## 构建及测试

VS Code 扩展在 `src/AutoCommit.Vscode` 独立构建：

```powershell
cd src/AutoCommit.Vscode
npm ci
npm test
npm run package
```

生成的 VS Code 专用 VSIX 可通过“扩展：从 VSIX 安装”安装；当前本地发布包见[最新本地发布](releases/LATEST.md)。该版本使用 VS Code 原生提交框，不执行自动提交或推送。

```powershell
dotnet build AutoCommit.sln
dotnet test tests/AutoCommit.Tests/AutoCommit.Tests.csproj
```

需要 Windows 和 .NET 8 SDK。SDK 安装在本机 `%LOCALAPPDATA%/AutoCommit/dotnet`，未修改全局 PATH；可用该目录下的 `dotnet.exe` 执行上述命令。

源码构建使用 .NET 8 SDK，或者配置相应 SDK 的 Visual Studio 2022 开发环境；使用 Visual Studio 开发时需要安装“.NET 桌面开发”和“Visual Studio 扩展开发”工作负载。支持安装到 VS 2019 不意味着源码支持直接由 VS 2019 编译（源码使用现代 C# 语法）。命令行构建只生成安装包，不自动部署到 VS。

## VS 实机验收清单

当前环境无法完成 VS GUI 验收，发布前在 VS 2019 和 VS 2022 分别检查：

- 缺少配置时可从提示进入设置，保存后回到提交说明，重新打开工具窗口不会清空已有说明。
