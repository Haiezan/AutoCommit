# AutoCommit

Visual Studio AI 提交助手的 Git 首版原型。分别提供 Visual Studio 2019（16.x，x86）与 Visual Studio 2022 17.14（x64）安装包，共享功能代码。

## 0.6.1 Release：剪贴板重试

复制遇到 `0x800401D0 / CLIPBRD_E_CANT_OPEN` 时异步重试最多 6 次，总等待约 1.5 秒；持续失败时选中原文并提示手动复制，不丢失说明、不显示复制成功。18 项自动化测试通过；VS 实机占用场景尚未验证。

## 0.6.0 Release：TFVC 与独立连接状态

VS2019 新增 TFVC 工作区支持，使用 VS 安装的 Team Explorer 客户端组件及其认证环境。请先在 Team Explorer 连接 TFS / Azure DevOps Server 并映射工作区；不需要把 TFS 凭据填入模型 API Key。

- 优先识别 Git；非 Git 目录尝试当前用户的 TFVC 本地工作区映射。自动选择项目/解决方案目录，也可手工指定工作区内子目录。
- 读取指定目录递归范围内的挂起更改；新增、编辑、删除、重命名和目录操作均提供元信息。文本以工作区基线与本地内容两段供模型比较，不是统一 diff。
- 只读取已经挂起的修改。先在 VS 中检测并挂起新增、删除等更改；不自动添加文件，不代表 Team Explorer 的勾选列表。
- 非 UTF 编码、二进制和超过 1MB 文件仅提供元信息；使用内容哈希检测变化。输入过大时拒绝，建议缩小目录范围。
- TFVC “签入 TFS 服务器”是远程写入。确认框明确目录和范围，签入前重新检查快照，评估冲突、签入说明和团队策略。不覆盖策略、不绕过门控签入。需工单、必填注释或门控流程时请复制到 Team Explorer 完成签入。
- 模型状态、仓库状态在底部分开显示，仓库识别失败不会覆盖模型测试结果。无仓库时仍可测试模型。
- `.auto` 位于当前选定的 TFVC 目录（Git 则位于仓库根目录），不会自动挂起这些配置文件。

依赖：VS2019 Team Explorer 的 TFVC 客户端组件。若提示 Microsoft.TeamFoundation 程序集缺失，请通过 VS Installer 修复 Team Explorer/相关工作负载，再重启 VS。

验证：VS2019 Release 编译及 14 项自动化测试通过（包括 TFVC 文本编码、二进制元信息和内容哈希测试）。**当前没有 TFS 服务和 VS 实机，TFVC 认证、工作区读取、策略、签入及 GUI 加载尚未联调验证**。请先在测试项目验证新增/编辑/删除/重命名、范围外修改不签入、读取后修改被拒绝、签入返回 Changeset，以及拒绝策略时保留说明。

## 0.5.0 Release：项目配置（历史版本）

首次成功识别并读取 Git 仓库时，在仓库根目录初始化 `.auto`。每个仓库共享一份配置，不为每个 csproj 重复创建。

- `.auto/model.json`：BaseUrl、Model、AllowHttp、MaxInputCharacters，可纳入版本控制；不要填写 API Key。
- `.auto/commit-rules.md`：项目提交规范，可编辑并共享。第一次创建时优先复制原 `.commit-rules.md`，否则使用完整内置规范；之后以 `.auto` 为准，不覆盖已有文件。
- `.auto/.gitignore`：排除常见本地凭据文件名，仅是辅助保护，不替代正确保管 Key。
- Key 在插件设置页填写并保存至 `%LOCALAPPDATA%/AutoCommit/credentials`，使用 DPAPI 加密，按项目路径与服务地址隔离。换电脑、用户、项目路径或服务地址后需重新填写。旧的全局 Key 不自动复制到项目凭据。
- 未识别仓库时保存的是全局默认设置，之后作为新仓库 model.json 的初始值。共享配置或规范修改后，点击“读取暂存变更”加载。
- 创建文件会在 Git 中显示为未跟踪文件，由用户决定是否暂存和共享；插件不会自动暂存。

**0.5.0 历史支持边界：TFS/Azure DevOps 托管的 Git 支持；TFVC 在 0.6.0 新增。** `.auto` 配置本身不依赖 Git，但当前插件仅在 Git 流程中初始化和使用。

Release 构建命令：`dotnet build AutoCommit.sln -c Release -t:Rebuild`。
发布文件位于 `releases/0.5.0`，含 VS 2019、VS 2022 独立 VSIX 及 SHA-256 校验值。安装包未做发布者签名，未上传市场；Release 指构建配置，不表示已通过 VS 实机验收。

## 0.4.0 交互更新

- 重新生成前明确确认覆盖，默认聚焦取消；包含手动修改时特别提示。
- 新响应成功且快照验证通过才替换原文；失败、超时、取消保留原文。
- 支持撤销最近一次替换，同时恢复上一版手动编辑、快照和原始 Token 信息。撤销会覆盖新的手动修改时再次确认。
- 读取变更、切换仓库保留说明；过期状态禁用直接提交，仍可复制。重新显示工具窗口不会自动清空内容。
- 生成期间结果只读；提交后保留说明和结果，禁止重复提交。
- 模型设置保存后收起；差异和规范分别折叠；编辑器随窗口高度伸缩，操作区固定且可换行。
- 默认主题资源适配、可访问名称、取消默认焦点、标题长度建议及明确状态文字。
- 连接测试与生成用量独立；展示的生成用量对应原始响应，手动编辑不会改变其数值。失败请求不以零用量代替未知。
- 网络、HTTP、身份配置及签名错误提供处理建议；保留 Git 原始失败输出帮助排查 hooks。

草稿与撤销历史仅保存在当前工具窗口内存中，不承诺关闭 VS 或重新创建窗口后恢复。

## 已实现

- 工具菜单入口、分区 WPF 工具窗口：可折叠模型配置、差异/规范选项卡、可编辑结果、固定底部操作区。
- 独立测试连接（仅发送固定文本，可能产生少量调用费用）、保存配置、进度与取消、结果字数提示。
- 自动识别选中项目、解决方案或活动文件所在 Git 仓库，保留手工指定入口；显示分支及变更统计。
- 差异与 Markdown 规范默认收起，按需展开。无仓库规范文件时使用完整内置规范。
- 显示最近一次模型调用的输入、输出、总 Token、缓存/推理子项、实际模型和耗时；未返回的字段显示“未提供”，不估算或累计。
- 审核后确认提交到本地 Git，提交前检查分支及暂存快照；保留 Git hooks 和签名设置，不推送。
- 自定义 OpenAI 兼容 Base URL、模型、API Key；支持本机和局域网兼容服务。
- 读取 `.auto/commit-rules.md`，可临时编辑提示规范；持久修改请编辑该文件。
- 生成、取消、编辑和复制；生成前后及复制前验证暂存快照。
- API Key 通过 DPAPI 按 Windows 用户加密，凭据位于 `%LOCALAPPDATA%/AutoCommit/credentials`，项目配置位于 `.auto`。
- 输入字符预算超限直接拒绝，不静默截断；禁止 HTTP 隐式启用和 HTTP 重定向。

## 使用

根据 Visual Studio 版本选择安装包，安装后重启，在“工具 → AutoCommit 提交助手”打开窗口：

| Visual Studio | 安装包 |
| --- | --- |
| 2019（16.x） | `src/AutoCommit.Vsix.VS2019/bin/Debug/net472/AutoCommit.Vsix.VS2019.vsix` |
| 2022（17.14） | `src/AutoCommit.Vsix/bin/Debug/net472/AutoCommit.Vsix.vsix` |

两个包均要求 .NET Framework 4.7.2 或更高版本。VS 2019 包使用 16.0 SDK 编译，安装清单限定 `[16.0,17.0)`；VS 2022 包使用 17.14 SDK。VSIX 构建工具统一使用 17.x，但不会作为扩展运行依赖打包。

1. 打开工具窗口自动识别仓库；切换项目后点击“识别当前项目”或“读取暂存变更”。在 VS 中暂存本次提交内容。识别失败时可以勾选“手工指定仓库”。
2. 填写 Base URL（例如 `http://localhost:11434/v1`）及实际已部署模型名。本机 HTTP 也需勾选允许 HTTP。无认证服务可以留空 Key。
3. 点击“测试连接”验证地址、认证和模型，成功后点击“保存配置”。
4. 读取变更，在“差异预览”和“提交规范”选项卡审核输入。
5. 点击“生成提交说明”，审核输出及用量。可复制到 VS 原生提交框，也可点击“提交到本地 Git”，检查确认框中的仓库、分支和完整说明后提交。

插件不会自动暂存或推送；仅在用户明确确认后提交。提交执行期间禁用取消，避免中断 Git 写入后无法判断结果；Git hooks 或签名工具可能需要在外部完成交互。请避免提交期间在其他窗口并发修改暂存区；提交前检查不是跨进程事务锁，hooks 也可修改内容。点击生成才会发送预览中的代码与规范；请确认服务地址适合接收该仓库代码。当前版本没有自动敏感信息检测。

## 构建及测试

```powershell
dotnet build AutoCommit.sln
dotnet test tests/AutoCommit.Tests/AutoCommit.Tests.csproj
```

需要 Windows 和 .NET 8 SDK。SDK 安装在本机 `%LOCALAPPDATA%/AutoCommit/dotnet`，未修改全局 PATH；可用该目录下的 `dotnet.exe` 执行上述命令。

源码构建使用 .NET 8 SDK，或者配置相应 SDK 的 Visual Studio 2022 开发环境；使用 Visual Studio 开发时需要安装“.NET 桌面开发”和“Visual Studio 扩展开发”工作负载。支持安装到 VS 2019 不意味着源码支持直接由 VS 2019 编译（源码使用现代 C# 语法）。命令行构建只生成安装包，不自动部署到 VS。

## VS 实机验收清单

当前环境无法完成 VS GUI 验收，发布前在 VS 2019 和 VS 2022 分别检查：

- 首次配置展开，保存后收起，重新打开工具窗口不会清空已有说明。
- 原文手工修改后再次生成：取消保留；失败保留；成功替换；撤销恢复。
- 生成期间编辑禁用；取消后恢复编辑，原文不变。
- 读取相同变更保留草稿；切换仓库或变更后标记过期并禁用提交。
- 规范有临时修改时切换仓库，取消加载应保留规范并准确标明来源。
- 测试连接不覆盖生成用量；编辑正文后仍标注原始响应 Token。
- 浅色、深色、高对比度、窄窗口、150%/200% DPI、Tab 导航及 Esc 取消。
- 提交确认默认取消；身份、hooks、签名失败保留说明；成功后不能重复提交。
