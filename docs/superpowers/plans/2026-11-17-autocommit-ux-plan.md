# AutoCommit 提交体验优化实施计划

依据：[提交体验优化设计](../specs/2026-11-17-autocommit-ux-design.md)

## 顺序

1. **配置读取变为只读**：将项目配置的读取与初始化分离；`CommitControl.ReadChangesAsync` 在缺少 `.auto` 时使用本机默认设置和内置规范；保存项目配置时才初始化文件；生成过程不再隐式保存。验证新仓库读取后没有新增文件，已有配置仍可加载。
2. **范围展示与确认**：在 `ChangeSnapshot` 增加结构化文件清单，由 Git/TFVC provider 提供；在窗口中显示来源、范围、文件数与文件清单；TFVC 使用“挂起更改”术语；用可滚动的确认窗口展示完整清单和说明。验证 Git 部分暂存及 TFVC 递归范围的显示与实际读取一致。
3. **连接与草稿状态**：服务地址、模型、HTTP 选项、Key 或项目变化时使连接测试状态失效；分别显示配置是否已保存；复制前重新读取并检查草稿快照，过期或无法验证时提供重新读取和明确继续复制。验证失败或取消不清除说明，也不提前写剪贴板。
4. **文档与发布入口**：更新 README 的安装包矩阵、首次使用步骤和 TFVC 支持边界；修正现有 `.auto/README.md` 的旧说明；核对初始化生成的说明。验证文档链接对应真实文件。
5. **回归与实机验收**：运行现有自动化测试和 Release 构建；有 VS 2019/2022 与 TFVC 测试服务时完成规格中的 GUI/服务器验收，记录无法在当前环境完成的项目。

## 实施原则

每一步完成后检查对应行为，再继续下一步。保留提交前快照校验、Git hooks 和签名、TFVC 团队策略检查、草稿撤销及剪贴板重试。若无法取得真实 VS 或 TFVC 环境，以构建和自动化测试作为本地证据，明确留下实机验收项。
